**勘误（推翻票面前提）**：`8086:0b3a/0b5b` **从来不是 ZED-M 的桥芯**——是机器人上真实存在的两台 RealSense：`8086:0b3a` = **D435i**（SN 254643061106，挂 Realtek hub 下 2-2.3，6 video 节点）与 `8086:0b5b` = **D405**（SN 260323071943，挂 Genesys hub 下 2-2.1.4，kern.log Sep 2 10:38:41 实录）。半枚举态 = **ZED-M 的 UVC（2b03:f682）缺席**，排查者把 bus2 上常驻的 RealSense UVC 误认成 ZED。另：「HID 单独落 USB2 总线」是本机**正常拓扑**（UVC@bus2 SS + HID@bus1，健康时也如此），非异常。

**根因一句话**【推断】：ZED-M 的 USB 连接路径（线缆/连接器触点）信号完整性退化——冷启动链路训练时 USB2 高速握手与 SuperSpeed 训练**双双失败**（HID 降级全速 12M、SS 静默不成链 → 半枚举），重插（触点擦拭/重新就位）即恢复。

## 3. 决定性相关律

【推导】同一根口同一相机，USB2 侧枚举速度完美预测 SS 链路：

| USB2 侧（HID）速度 | SS 链路（UVC） | 出现场景 |
|---|---|---|
| 480M high-speed | ✅ 成链 | 健康窗（Aug 25/26、Sep 1 傍晚） |
| 12M full-speed（高速握手失败降级） | ❌ 不成链（静默） | 全部半枚举冷启 |
| 12M（chirp 失败但 SS 已训练） | ✅ 在链 | 当前态（10:24 重插后：SS 5000M + HID 12M） |

USB2 chirp 握手与 SS 链路训练是**两条独立线对上的独立模拟过程**，同时失败只能指向公共物理路径（连接器/线缆触点），而非设备固件或主机驱动逻辑。

## 4. 机理解释

- **为何"G1 断电后"相关**【推断】：冷启动是链路唯一从头训练的时刻（会话中已训练的链路对劣化更容忍）；G1 断电/换电 → Jetson 冷启 → 触发冷训练 → 撞上劣化触点。非 G1 电源本身因果（Jetson 供电来自 G1，但无任何电源类内核事件佐证预算不足）。
- **为何重插即修**：插拔动作擦拭/重就位触点，重新训练时信号裕量恢复。三次首插失败 + 会话中 URB 死亡说明裕量边缘化、随振动/姿态漂移。
- **为何 SDK 时开时不开**（票面 10:40 OK / 15:58 FAIL）：取决于当时链路是"成链"还是"URB 死亡"态，与枚举成功与否解耦。
- **趋势**：Jul 20 前冷启基本全健康（kern.log 早期 HIGH+SS 为主）→ Jul 20–Aug 26 混合 → **Aug 27 后 14/15 恶化**：渐进性退化，符合触点氧化/磨损轨迹。
